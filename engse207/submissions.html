    How it works

    ระบบตรวจอะไร

    • ตรวจว่ามีไฟล์หรือโฟลเดอร์ตาม path ใน branch main ชื่อไฟล์และตำแหน่งต้องตรงทุกตัวอักษร ดู path ทั้งหมดที่หน้าสิ่งที่ต้องส่ง
    • จุดตรวจที่ใช้ tag (t07-a5a, t14-submit) ต้องมี tag นั้นบน GitHub ด้วย ไม่ใช่แค่ในเครื่อง ใช้ git push origin <ชื่อ tag>
    • งานเดี่ยว (ไฟล์ใน individual/ ที่ลงท้ายด้วยรหัส) ตรวจไฟล์ของสมาชิกทุกคนตามรหัสในแบบลงทะเบียน แสดงสถานะรายคนด้วยรหัสที่ปิดบางส่วน ช่องของทีมขึ้น ส่งแล้ว x/y คน จนกว่าจะครบทุกคน · ใส่เลขท้ายรหัสของตัวเองที่ช่อง เลขท้ายรหัสนักศึกษา ด้านบน ระบบจะสรุปงานเดี่ยวของคุณให้
    • เวลาที่แสดงคือเวลา commit แรกที่ไฟล์นั้นเข้ามา ถ้าหลังเวลาครบกำหนดจะขึ้นว่าส่งหลังกำหนด
    • งาน D02 และ I01 มีการตรวจความครบถ้วนเบื้องต้น (เช่น ข้อความแม่แบบค้าง, รายชื่อสมาชิก, คำตอบ C1–C8, ผล check-docker.sh) ถ้าขึ้น ⚠ ให้แก้แล้ว push ขึ้น main จากนั้นกดปุ่ม ตรวจทีมนี้ใหม่ ได้เลย (อาจารย์ตรวจเนื้อหาเชิงลึกและให้คะแนนแยก)

    รหัสงานD งานทีมที่เป็นไฟล์ใน repo ทำต่อเนื่อง ไม่มีคะแนนแยก ตรวจรวมในจุดตรวจP งานทีมเตรียมระบบก่อนคาบ เลขคือคาบที่ใช้ (P02 ก่อน T02)I งานเดี่ยว ไม่คิดคะแนนL บันทึกแล็บของทีม เลขคือครั้งที่ทำแล็บA งานที่มีคะแนน A1–A9 (A9L บันทึกสะสมของ A9)REG ลงทะเบียนทีมH06 ARCH-06 ส่งต่อ
