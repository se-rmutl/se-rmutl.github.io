ขั้นที่ 1เขียน Dockerfile ของแอปเอง แล้ว build image 20–30 นาที

Dockerfile คือสูตรบอกวิธีสร้าง image ซึ่งเป็นชุดไฟล์ที่มีทั้ง Node.js dependency และโค้ดของเราพร้อมรัน สร้างไฟล์ใหม่ app/Dockerfile แล้วพิมพ์ทีละบรรทัด อ่านคอมเมนต์ไปด้วย

app/Dockerfileฉบับที่เราเขียนเอง

# 1) เริ่มจาก image ที่มี Node.js 24 อยู่แล้ว · แทนการติดตั้ง Node.js เองใน 0A
FROM node:24-alpine

# 2) โฟลเดอร์ทำงานข้างใน container
WORKDIR /app

# 3) คัดลอกรายการ dependency แล้วติดตั้ง · แทน npm ci ใน 0A (ไม่เอา nodemon)
COPY package.json package-lock.json ./
RUN npm ci --omit=dev

# 4) คัดลอกโค้ดที่เหลือ รวมถึงที่เราแก้ใน 0A
COPY . .

# 5) บอกว่าแอปฟังพอร์ต 3000 และคำสั่งที่ใช้เริ่มแอป
EXPOSE 3000
CMD ["node", "server.js"]
.dockerignore สำคัญกับเครื่องที่ทำ 0A แล้ว

ใน 0A เรา npm ci บนเครื่อง จึงมีโฟลเดอร์ app/node_modules ที่สร้างสำหรับระบบของเรา ถ้า COPY . . คัดลอกโฟลเดอร์นี้ไปทับของใน image ผลอาจเพี้ยน ไฟล์ app/.dockerignore ที่มากับโค้ดกันไว้แล้ว ลองดู cat app/.dockerignore ต้องเห็น node_modules

docker build -t tb-app:mine ./app       # ครั้งแรกดาวน์โหลด node:24-alpine 1–3 นาที
docker images tb-app
ควรเห็น ขั้น [1/5]…[5/5] ตามบรรทัดใน Dockerfile แล้ว naming to docker.io/library/tb-app:mine · docker images มี tb-app แท็ก mine พร้อมขนาด · วาง Dockerfile และผล docker images ในช่องหลักฐาน 2

ลอง build ซ้ำอีกครั้งทันที จะเสร็จในไม่กี่วินาที เพราะทุกขั้นขึ้นคำว่า CACHED Docker เก็บผลของแต่ละบรรทัดไว้ ถ้าไฟล์ที่บรรทัดนั้นใช้ไม่เปลี่ยน ก็ใช้ของเดิม นี่คือเหตุผลที่คัดลอก package.json ก่อนโค้ด

ขั้นที่ 2รัน container ของแอปตัวเดียว 10 นาที

container คือโปรแกรมที่กำลังรันจาก image หนึ่ง image สร้าง container ได้หลายตัว ลองรันแอปโดยยังไม่มีฐานข้อมูลใน Docker

docker run --rm --name tb-app -p 3000:3000 tb-app:mine
# --rm      ลบ container ทิ้งเมื่อหยุด
# -p 3000:3000   พอร์ตเครื่องเรา : พอร์ตใน container

หน้าต่างนี้จะค้างแสดง log ของแอป เปิดเบราว์เซอร์ที่ http://localhost:3000 และหน้าต่าง Terminal ที่สอง

curl -s localhost:3000/api/health; echo
ควรเห็น หน้าเว็บเปิดได้ แต่ขึ้น “โหลดรายการงานไม่ได้” · health ได้ {"app":"ok","db":"down","error":"connect ECONNREFUSED 127.0.0.1:5432"} (บางเครื่องเป็น ::1:5432) · วางผลและเหตุผลในช่องหลักฐาน 3
ทำไมต่อไม่ได้ ทั้งที่ PostgreSQL ของ 0A ยังเปิดอยู่

แอปไม่ได้ตั้ง DB_HOST จึงใช้ค่าตั้งต้น localhost แต่ localhost ข้างใน container หมายถึงตัว container เอง ไม่ใช่เครื่องของเรา ใน container นี้ไม่มีใครฟังพอร์ต 5432 จึงได้ ECONNREFUSED ส่วนหน้าเว็บยังเปิดได้ เพราะไฟล์ใน public/ ไม่ต้องใช้ฐานข้อมูล

กลับไปหน้าต่างแรก กด Ctrl+C เพื่อหยุด container (ถูกลบทิ้งเพราะใส่ --rm)

ขั้นที่ 3ย้ายฐานข้อมูลเข้า container 20 นาที

สร้าง เครือข่าย สำหรับให้ container คุยกัน แล้วรัน PostgreSQL จาก image สำเร็จรูป อ่านคอมเมนต์ว่าแต่ละบรรทัดแทนอะไรใน 0A

docker network create tb-net

docker run -d --name tb-db --network tb-net \
  -e POSTGRES_USER=taskboard \
  -e POSTGRES_PASSWORD=taskboard_dev \
  -e POSTGRES_DB=taskboard \
  -p 5433:5432 \
  -v tb-pgdata:/var/lib/postgresql/data \
  -v "$PWD/db/init":/docker-entrypoint-initdb.d:ro \
  postgres:16-alpine
ส่วนของคำสั่งแทนอะไรใน 0A
-dรันเบื้องหลัง แทนการเปิด Postgres.app หรือ service postgresql start
-e POSTGRES_USER … POSTGRES_DBCREATE ROLE และ CREATE DATABASE ในขั้น 3.1 ของ 0A image ทำให้ตอนเริ่มครั้งแรก
-p 5433:5432เปิดประตูจากเครื่องเราพอร์ต 5433 เข้าพอร์ต 5432 ใน container
-v tb-pgdata:/var/lib/…/dataที่เก็บข้อมูลของฐานข้อมูล อยู่ใน volume ชื่อ tb-pgdata ไม่หายเมื่อลบ container
-v "$PWD/db/init":/docker-entrypoint-initdb.d:roการรัน 01-schema.sql และ 02-seed.sql ด้วยมือ image รันทุกไฟล์ในโฟลเดอร์นี้ให้ เฉพาะตอนที่ volume ยังว่าง
docker ps
docker logs tb-db 2>&1 | grep -E "docker-entrypoint-initdb.d/|ready to accept"
psql "postgresql://taskboard:taskboard_dev@localhost:5433/taskboard" -c "SELECT id, name FROM members;"
ควรเห็น tb-db สถานะ Up · log มีบรรทัด running /docker-entrypoint-initdb.d/01-schema.sql และ 02-seed.sql แล้ว ready to accept connections · psql ผ่านพอร์ต 5433 ได้สมาชิก 5 คน รวมชื่อที่เพิ่มใน 0A ข้อ 6.3 (เพราะ mount โฟลเดอร์ db/init ของเรา) · วางผล psql ในช่องหลักฐาน 4

ขั้นที่ 4ให้สอง container คุยกัน 15 นาที

docker run -d --name tb-app --network tb-net -p 3000:3000 -e DB_HOST=tb-db tb-app:mine
docker ps
curl -s localhost:3000/api/health; echo
docker logs tb-app
ควรเห็น health "db":"ok" · เปิดหน้าเว็บ เห็นบอร์ด 7 งาน ชื่อคุณในช่องผู้รับผิดชอบ และบรรทัด about จาก 0A · วางผล health ในช่องหลักฐาน 5
ทำไมครั้งนี้ต่อได้
  • -e DB_HOST=tb-db ส่งค่าเข้าไปแทนค่าตั้งต้น localhost ใน server.js (จำกล่อง “แอปรู้ได้อย่างไร” ใน 0A ขั้นที่ 4)
  • ทั้งสองอยู่ในเครือข่าย tb-net Docker จึงแปลงชื่อ tb-db เป็นที่อยู่ของ container ฐานข้อมูลให้
  • ในเครือข่าย แอปต่อพอร์ต 5432 ของ container โดยตรง ส่วน 5433 มีไว้ให้โปรแกรมบนเครื่องเรา เช่น psql ในขั้นที่ 3

ลองนับดู: ต้องพิมพ์ 3 คำสั่งยาว ๆ จำชื่อ ค่าตั้ง พอร์ต และลำดับ (ฐานข้อมูลก่อนแอป) ทุกครั้ง ขั้นต่อไปจะเขียนสิ่งเหล่านี้ลงไฟล์เดียว เก็บกวาดก่อน

docker rm -f tb-app tb-db
docker network rm tb-net
docker volume rm tb-pgdata

ขั้นที่ 5เขียน docker-compose.yml เอง ทีละรอบ 30–40 นาที

Docker Compose อ่านไฟล์ YAML ที่บอกว่าระบบมี service อะไรบ้าง แต่ละตัวตั้งค่าอย่างไร แล้วสร้างเครือข่ายให้เอง ชื่อ service ใช้เป็นชื่อเครื่องในเครือข่าย YAML ใช้การเยื้องด้วย ช่องว่าง 2 ตัว ห้ามใช้ Tab

5.1 รอบที่ 1 · สอง service แบบน้อยที่สุด

docker-compose.ymlสร้างใหม่ที่โฟลเดอร์ tb-local

services:
  app:
    build: ./app                 # สร้าง image จาก app/Dockerfile ของเรา
    ports:
      - "3000:3000"

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: taskboard
      POSTGRES_PASSWORD: taskboard_dev
      POSTGRES_DB: taskboard
    ports:
      - "5433:5432"

ทายก่อนรัน: health จะได้อะไร และหน้าเว็บจะมีงานไหม จดคำทายไว้ในช่องหลักฐาน 6 แล้วค่อยรัน

docker compose up -d --build
docker compose ps
curl -s localhost:3000/api/health; echo
ควรเห็น ชื่อ container ขึ้นต้นด้วยชื่อโฟลเดอร์ เช่น tb-local-app-1 tb-local-db-1 · health ยัง "db":"down" เพราะแอปยังต่อ localhost · และถึงต่อได้ก็ยังไม่มีตาราง เพราะยังไม่ได้ส่งสคริปต์ db/init ให้ฐานข้อมูล

5.2 รอบที่ 2 · บอกแอปว่าฐานข้อมูลอยู่ที่ไหน และให้ฐานข้อมูลมีข้อมูล

แก้ไฟล์ให้เป็นแบบนี้ (เพิ่มบรรทัดที่มีคอมเมนต์ “รอบ 2”)

services:
  app:
    build: ./app
    ports:
      - "3000:3000"
    environment:
      DB_HOST: db                # รอบ 2 · ชื่อ service ของฐานข้อมูล

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: taskboard
      POSTGRES_PASSWORD: taskboard_dev
      POSTGRES_DB: taskboard
    ports:
      - "5433:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data              # รอบ 2 · ข้อมูลอยู่ใน volume
      - ./db/init:/docker-entrypoint-initdb.d:ro     # รอบ 2 · สคริปต์สร้างตารางและข้อมูลตั้งต้น

volumes:
  pgdata:                        # รอบ 2 · ประกาศ volume ที่ใช้ข้างบน
docker compose up -d             # Compose สร้างใหม่เฉพาะ service ที่ค่าเปลี่ยน
docker compose ps
curl -s localhost:3000/api/health; echo
docker compose logs -f app       # สร้างงานบนหน้าเว็บแล้วดู log · Ctrl+C เพื่อเลิกดู
ควรเห็น health "db":"ok" · บอร์ด 7 งาน และสมาชิก 5 คน · log มี [api] POST /api/tasks -> 201 เมื่อสร้างงาน (ถ้า health ยัง down ในวินาทีแรก รอ 5 วินาทีแล้วลองใหม่ เหตุผลอยู่ในรอบที่ 3)

5.3 รอบที่ 3 · ให้แอปรอจนฐานข้อมูลพร้อม

Compose เริ่มทุก service เกือบพร้อมกัน แอปจึงอาจเริ่มก่อนที่ PostgreSQL พร้อมรับคำขอ เพิ่ม healthcheck ให้ db และให้ app รอจน db ผ่าน

  app:
    build: ./app
    ports:
      - "3000:3000"
    environment:
      DB_HOST: db
    depends_on:                  # รอบ 3
      db:
        condition: service_healthy

  db:
    image: postgres:16-alpine
    # … environment ports volumes เหมือนรอบ 2 …
    healthcheck:                 # รอบ 3 · ถามฐานข้อมูลทุก 3 วินาทีว่าพร้อมหรือยัง
      test: ["CMD-SHELL", "pg_isready -U taskboard -d taskboard"]
      interval: 3s
      timeout: 3s
      retries: 20
ดูไฟล์เต็มหลังรอบที่ 3 (เทียบกับของคุณ) 
services:
  app:
    build: ./app
    ports:
      - "3000:3000"
    environment:
      DB_HOST: db
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: taskboard
      POSTGRES_PASSWORD: taskboard_dev
      POSTGRES_DB: taskboard
    ports:
      - "5433:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./db/init:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U taskboard -d taskboard"]
      interval: 3s
      timeout: 3s
      retries: 20

volumes:
  pgdata:
docker compose down -v           # ลบทั้งหมดรวม volume เพื่อเริ่มจากศูนย์
docker compose up -d --build     # ดูข้อความระหว่างรอ
docker compose ps
ควรเห็น ระหว่าง up มีบรรทัดว่า db กำลังรอให้ healthy แล้ว app จึงเริ่ม · ps เห็น db Up (healthy) · health ok ทันทีหลัง up เสร็จ · วางไฟล์ docker-compose.yml ฉบับเต็มของคุณ และผล docker compose ps ในช่องหลักฐาน 7

5.4 ทดลองการแก้โค้ดกับไฟล์ของเรา

แก้ app/server.js ในส่วน /api/about ที่เพิ่มใน 0A เปลี่ยน version: "v1-monolith" เป็น version: "v1-docker" บันทึก แล้วเรียก curl -s localhost:3000/api/about

ควรเห็น ยังได้ v1-monolith เหมือนเดิม เพราะโค้ดถูกคัดลอกเข้า image ตอน build แล้ว ต้อง docker compose up -d --build จึงเห็น v1-docker · จดผลในช่องหลักฐาน 8

ทบทวนตรวจความเข้าใจ และสรุป

ตอบในใจก่อน แล้วคลิกดูแนวคำตอบ
  1. Dockerfile ของเรามาแทนขั้นไหนของ 0A บ้างแนวคำตอบFROM node:24-alpine แทนการติดตั้ง Node.js · COPY package*.json + RUN npm ci แทน npm ci บนเครื่อง · CMD แทนการพิมพ์คำสั่งเริ่มแอป ทุกคนที่ build จะได้รุ่นเดียวกัน
  2. ขั้นที่ 2 ทำไมแอปต่อฐานข้อมูลไม่ได้ ทั้งที่ PostgreSQL บนเครื่องเปิดอยู่แนวคำตอบแอปใช้ค่าตั้งต้น localhost ซึ่งข้างใน container หมายถึงตัว container เอง ไม่ใช่เครื่องเรา ในนั้นไม่มีอะไรฟังพอร์ต 5432
  3. แอปใน container ต่อฐานข้อมูลที่ db:5432 แต่ psql บนเครื่องต่อที่ localhost:5433 ทำไมไม่เหมือนกันแนวคำตอบแอปอยู่ในเครือข่ายเดียวกับฐานข้อมูล จึงเรียกด้วยชื่อ service และพอร์ตใน container ส่วน psql อยู่บนเครื่องเรานอกเครือข่ายนั้น ต้องเข้าทางพอร์ตที่จับคู่ไว้ 5433 → 5432
  4. สคริปต์ใน db/init รันตอนไหน ทำไม up รอบสองจึงไม่รันซ้ำแนวคำตอบimage ของ PostgreSQL รันไฟล์ในโฟลเดอร์นี้เฉพาะตอนที่ volume ข้อมูลยังว่าง รอบต่อไป volume มีข้อมูลแล้วจึงข้าม ต้อง down -v ถ้าอยากเริ่มใหม่ (ข้อมูลหาย)
  5. ทำไมไฟล์จริงของ T02 มี ./app:/app และใช้ npm run dev ขณะที่ของเราไม่มีแนวคำตอบเพื่อให้แก้โค้ดในเครื่องแล้ว container เห็นทันทีและ nodemon รีสตาร์ตให้ ไม่ต้อง build ใหม่ทุกครั้ง เหมาะกับช่วงพัฒนาและการเรียนในห้อง ส่วนแบบของเราเหมือนการส่งมอบ โค้ดอยู่ใน image ตายตัว
สรุป Lab 0B
  • image = สูตรที่ build แล้ว · container = โปรแกรมที่รันจาก image · Dockerfile = วิธีสร้าง image ของแอป
  • -p เครื่องเรา:container เปิดประตูจากเครื่องเรา · ในเครือข่ายของ Docker เรียกกันด้วยชื่อ
  • ข้อมูลที่ต้องอยู่รอดเก็บใน volume · สคริปต์ db/init รันครั้งเดียวตอน volume ว่าง
  • docker-compose.yml รวมทุกคำสั่ง docker run ไว้ในไฟล์เดียว เปิดทั้งระบบด้วย docker compose up
  • ไฟล์จริงของ T02 เพิ่ม bind mount + nodemon และค่าจาก .env เพื่อให้แก้โค้ดได้ทันทีและเปลี่ยนค่าได้โดยไม่แก้ไฟล์
