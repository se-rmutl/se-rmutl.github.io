ส่วนที่ 2วงจรการใช้งานหนึ่งรอบ: เปิด ทำงาน ปิด

2.1 เปิดระบบครั้งแรก

cd ~/Desktop/engse207-2569-s1-cloudcats
docker compose up -d --build      # ครั้งแรก 2–5 นาที · ครั้งต่อไปไม่กี่วินาที
docker compose ps

ผลของ docker compose ps ที่ถูกต้อง (ตัดคอลัมน์ IMAGE COMMAND CREATED ออกให้สั้น)

NAME                               SERVICE   STATUS                  PORTS
engse207-2569-s1-cloudcats-app-1   app       Up 2 minutes            0.0.0.0:3000->3000/tcp
engse207-2569-s1-cloudcats-db-1    db        Up 2 minutes (healthy)  0.0.0.0:5433->5432/tcp
  • ชื่อ container = ชื่อโฟลเดอร์ + ชื่อ service + ลำดับ แต่ละทีมจึงได้ container และ volume ของตัวเอง ไม่ชนกัน
  • SERVICE คือชื่อที่ใช้ในคำสั่ง เช่น logs app stop db ไม่ต้องพิมพ์ชื่อ container เต็ม
  • PORTS อ่านว่า พอร์ตเครื่องเรา → พอร์ตใน container (รายละเอียดใน เอกสารครั้งที่ 3 ส่วน 3.3)
  • ถ้า db เป็น (health: starting) ให้รอ 5–10 วินาทีแล้ว ps ใหม่ app จะเริ่มหลัง db พร้อมเท่านั้น

เปิด http://localhost:3000 ต้องเห็นบอร์ด 3 คอลัมน์ งานตัวอย่าง 7 งาน และ http://localhost:3000/api/health ต้องได้ {"app":"ok","db":"ok",…}

2.2 ระหว่างทำงาน

เปิดหน้าต่างที่สองไว้ดู log ตลอดแล็บ แล้ววางหน้าเว็บกับแท็บ Network ของ DevTools (macOS: Option+Cmd+I · Windows: F12) ไว้ข้างกัน

docker compose logs -f app        # ดู log สด · Ctrl+C เพื่อเลิกดู แอปยังทำงานต่อ

2.3 ปิดระบบ

docker compose down               # ลบ container และเครือข่าย ข้อมูลในฐานข้อมูลยังอยู่ใน volume
down กับ down -v ไม่เหมือนกัน

docker compose down -v ลบ volume ด้วย ข้อมูลที่ทีมสร้างไว้ทั้งหมดหายและกลับเป็นข้อมูลตั้งต้น 7 งานเมื่อ up ครั้งถัดไป ใช้เฉพาะเมื่อ ตั้งใจ เริ่มข้อมูลใหม่ หรือใบงานสั่งให้ลอง

ส่วนที่ 3แก้อะไรแล้วต้องสั่งอะไร

คำถามที่พบบ่อยที่สุดในแล็บคือ “แก้แล้วทำไมไม่เห็นผล” คำตอบขึ้นกับว่าแก้ไฟล์ไหน เพราะแต่ละไฟล์เข้าไปถึง container คนละทาง

แก้อะไรต้องสั่งเพราะ
app/server.jsไม่ต้องสั่งอะไร ดู log ว่าแอปรีสตาร์ตแล้วโฟลเดอร์ app/ ถูก mount เข้า container และ nodemon เฝ้าไฟล์นี้อยู่ บันทึกแล้วแอปเริ่มใหม่เอง
app/public/* (หน้าเว็บ)รีเฟรชเบราว์เซอร์ (ถ้ายังเห็นของเก่า Cmd+Shift+R หรือ Ctrl+Shift+R)เซิร์ฟเวอร์ส่งไฟล์จากโฟลเดอร์ที่ mount ไว้ แต่เบราว์เซอร์อาจจำไฟล์เก่า
.env หรือ docker-compose.ymldocker compose up -dค่า environment ถูกใส่ตอน สร้าง container · up -d สร้างใหม่เฉพาะตัวที่ค่าเปลี่ยน · restart ใช้ไม่ได้ผล
app/package.json หรือ app/Dockerfiledocker compose up -d --builddependency อยู่ใน image ต้องสร้าง image ใหม่
db/init/*.sqldocker compose down -v แล้ว up -dไฟล์ใน db/init รันเฉพาะตอน volume ยังว่าง · ข้อมูลเดิมหาย
ไม่ได้แก้อะไร แค่อยากให้แอปเริ่มใหม่docker compose restart appหยุดแล้วเริ่ม container เดิม ค่าเดิมทุกอย่าง

ส่วนที่ 4คำสั่ง Docker Compose แยกตามงาน

รูปแบบคือ docker compose <คำสั่ง> [ชื่อ service] ไม่ใส่ชื่อ service แปลว่าทำกับทุก service ในไฟล์ ป้าย T02 T03 บอกว่าใบงานครั้งไหนใช้

4.1 เปิด ปิด และเริ่มใหม่

คำสั่งทำอะไรข้อมูลในฐานข้อมูล
up -d --build T02สร้าง image ถ้าจำเป็น แล้วเปิดทุก service เบื้องหลัง (-d = ไม่ผูกกับหน้าต่างนี้)อยู่
up -d T03เปิด หรือสร้าง container ใหม่เฉพาะตัวที่ค่าตั้งเปลี่ยนอยู่
stop db · start db T03หยุดชั่วคราว แล้วเริ่มตัวเดิมอยู่
restart app T03หยุดแล้วเริ่มตัวเดิมทันทีอยู่
down T02ลบ container และเครือข่ายอยู่
down -v T03ลบ container เครือข่าย และ volumeหาย

4.2 ดูสถานะและส่วนประกอบ

คำสั่งทำอะไร
docker compose ps T02container ของโฟลเดอร์นี้ สถานะ และพอร์ต
docker compose ps -aรวม container ที่หยุดหรือล้มไปแล้ว ใช้ตอนหา container ที่หายจากรายการ
docker compose images T03image ที่ container ใช้ และขนาด
docker volume ls T03volume ทั้งเครื่อง ของทีมลงท้าย _pgdata
docker pscontainer ที่รันอยู่ ทั้งเครื่อง ทุกโปรเจกต์ ใช้หาว่าใครจับพอร์ตอยู่
docker compose configแสดงไฟล์ Compose หลังแทนค่าจาก .env แล้ว ใช้ตรวจว่าค่าที่แก้เข้าไปจริง

4.3 ดู log

คำสั่งทำอะไร
docker compose logs -f app T02ตาม log ของแอปแบบสด
docker compose logs --tail 30 appดู 30 บรรทัดล่าสุดแล้วจบ เหมาะกับคัดลอกลงบันทึกแล็บ
docker compose logs --since 5m appเฉพาะ 5 นาทีที่ผ่านมา
docker compose logs db T03log ของ PostgreSQL ดูตอนฐานข้อมูลเริ่มไม่ขึ้นหรือมีคนต่อไม่ได้
docker compose logs -fทุก service ปนกัน มีชื่อ service นำหน้าแต่ละบรรทัด

4.4 เข้าไปทำงานข้างใน container

คำสั่งทำอะไร
docker compose exec app shเปิด shell ใน container app (พิมพ์ exit เพื่อออก) ลอง ls หรือ env | grep DB
docker compose exec app printenv REPORT_COST_MSดูค่า environment หนึ่งตัวที่แอปเห็นจริง
docker compose exec app node -e "…" T03รัน JavaScript สั้น ๆ ใน container เช่นถามว่าชื่อ db ได้ IP อะไร
docker compose exec db psql -U taskboard -d taskboardเข้า PostgreSQL ใน container db (ดู ส่วนที่ 6)
exec กับ run ต่างกัน

exec เข้าไปใน container ที่ รันอยู่แล้ว ส่วน docker compose run สร้าง container ใหม่อีกตัว ในวิชานี้ใช้ exec อย่างเดียว ถ้า exec ขึ้นว่า service is not running แปลว่ายังไม่ได้ up

4.5 ทดลองในครั้งที่ 3

ใบงาน T03 ส่วน B ใช้คำสั่งต่อไปนี้ ให้ทายผลก่อนกด แล้วจดตัวเลขจริง คู่มือนี้จึงไม่บอกผลไว้

docker compose stop db  ·  docker compose start db       # E1
docker compose restart app                              # E2
docker compose up -d                                    # E3 หลังแก้ REPORT_COST_MS ใน .env
docker compose up -d --scale app=2  ·  --scale app=1    # E4
docker compose down  ·  down -v  ·  up -d               # E5

4.6 ดูแลพื้นที่ดิสก์ (เฉพาะเครื่องตัวเอง)

docker system df          # image container volume ใช้ที่ไปเท่าไร
docker image prune        # ลบ image ที่ไม่มีชื่อและไม่มีใครใช้ ระบบถามยืนยันก่อน

ห้ามใช้คำสั่ง prune บน iMac ของห้องแล็บ เพราะลบของทีมอื่นที่ใช้เครื่องเดียวกันได้

ส่วนที่ 5อ่าน log และตรวจด้วย curl

5.1 อ่านหนึ่งบรรทัดของ log

[api] POST /api/tasks -> 201 (4 ms)
  │     │    │             │    └─ เวลาที่เซิร์ฟเวอร์ใช้ นับตั้งแต่ Express เริ่มรับคำขอ
  │     │    │             └────── status code ที่ตอบกลับ
  │     │    └──────────────────── path ของคำขอ
  │     └───────────────────────── HTTP method
  └─────────────────────────────── ป้ายบอกว่ามาจากส่วนไหนของแอป

บรรทัดที่ขึ้นต้น [api] … failed: คือรายละเอียดของ error ที่ผู้ใช้ไม่เห็น ใช้ชี้หาสาเหตุ เวลาในวงเล็บ ไม่รวม เวลาที่คำขอรอคิวก่อนถึง Express ครั้งที่ 3 จะเห็นว่าเรื่องนี้สำคัญอย่างไรเมื่อเทียบกับเวลาในแท็บ Network

5.2 curl: ยิงคำขอจาก Terminal โดยไม่ผ่านหน้าเว็บ

ใช้แยกว่าปัญหาอยู่ที่หน้าเว็บหรือที่เซิร์ฟเวอร์ ถ้า curl ได้ผลถูกแต่หน้าเว็บผิด ปัญหาอยู่ฝั่งเบราว์เซอร์

curl -s localhost:3000/api/health                      # สุขภาพของแอปและฐานข้อมูล
curl -s localhost:3000/api/tasks                       # งานทั้งหมดเป็น JSON
curl -i localhost:3000/api/tasks                       # -i แสดงบรรทัด status และ header ด้วย
curl -s -X POST localhost:3000/api/tasks \
     -H 'Content-Type: application/json' \
     -d '{"title":"ทดสอบจาก curl"}'                     # สร้างงานใหม่ ต้องได้งานที่สร้างกลับมา

5.3 health loop: วัดว่าระบบใช้ไม่ได้นานเท่าไร

ครั้งที่ 3 ใช้คำสั่งนี้ในหน้าต่างแยก เพื่อยิง health ทุกครึ่งวินาทีระหว่างทดลอง

while true; do
  echo "$(date +%T) $(curl -s -o /dev/null -w '%{http_code}' localhost:3000/api/health)"
  sleep 0.5
done

วางทั้ง 4 บรรทัดพร้อมกันได้ หรือพิมพ์เป็นบรรทัดเดียวแบบในใบงาน T03 ก็ได้ผลเหมือนกัน ผลที่ได้เป็นบรรทัดละหนึ่งครั้ง เช่น 11:20:01 200

ส่วนความหมาย
while true; do … doneวนไม่รู้จบ กด Ctrl+C เพื่อหยุด
date +%Tเวลาตอนนี้ ชั่วโมง:นาที:วินาที ใช้คำนวณช่วงที่ใช้ไม่ได้
-o /dev/nullทิ้งเนื้อหาคำตอบ ไม่ต้องแสดง
-w '%{http_code}'พิมพ์เฉพาะ status code · 000 แปลว่าต่อไม่ได้เลย ไม่มีใครฟังพอร์ตนั้น
sleep 0.5รอครึ่งวินาทีก่อนยิงรอบถัดไป

คำสั่งนี้เป็นภาษา bash ใช้ได้ใน Terminal ของ macOS และ Ubuntu (WSL) ใช้ใน PowerShell ไม่ได้

ส่วนที่ 6ดูข้อมูลในฐานข้อมูลด้วย psql

docker compose exec db psql -U taskboard -d taskboard
\dt                                              # มีตารางอะไรบ้าง
\d tasks                                         # คอลัมน์และข้อกำหนด (constraint) ของตาราง tasks
SELECT id, title, status, assignee_id FROM tasks ORDER BY id;
SELECT * FROM members;
SELECT status, COUNT(*) FROM tasks GROUP BY status;
\q                                               # ออก
  • คำสั่ง SQL ต้องจบด้วย ; ถ้าพรอมต์เปลี่ยนเป็น taskboard-# แปลว่ายังรอเครื่องหมายนี้อยู่
  • UPDATE และ DELETE เปลี่ยนข้อมูลจริงทันที ไม่มีปุ่มย้อนกลับ ใช้เฉพาะเมื่อใบงานสั่ง
  • อยากใช้โปรแกรมดูฐานข้อมูลบนเครื่อง เช่น DBeaver หรือ TablePlus ให้ต่อที่ host localhost port 5433 ผู้ใช้ taskboard รหัส taskboard_dev ฐานข้อมูล taskboard (ค่าเริ่มต้นใน .env.example ใช้ในเครื่องเท่านั้น)

ส่วนที่ 7ค่าตั้งและไฟล์ .env

ไม่มีไฟล์ .env ระบบใช้ค่าเริ่มต้นที่เขียนใน docker-compose.yml ถ้าต้องการเปลี่ยนค่า ให้คัดลอกจากไฟล์ตัวอย่างก่อน

cp .env.example .env                    # ทำครั้งเดียว
code .env                               # แก้ค่า เช่น APP_PORT=3001 หรือ REPORT_COST_MS=3000 แล้วบันทึก
docker compose up -d                    # ให้ Compose สร้าง container ที่ค่าเปลี่ยนขึ้นใหม่
docker compose exec app printenv REPORT_COST_MS   # ตรวจว่าแอปเห็นค่าใหม่แล้ว
ค่าค่าเริ่มต้นใช้เมื่อ
APP_PORT3000พอร์ต 3000 ของเครื่องมีโปรแกรมอื่นใช้อยู่
DB_HOST_PORT5433พอร์ต 5433 ของเครื่องชน
POSTGRES_USER POSTGRES_PASSWORD POSTGRES_DBtaskboard · taskboard_dev · taskboardปกติไม่ต้องแก้ ถ้าแก้หลังสร้าง volume แล้ว แอปจะต่อฐานข้อมูลไม่ได้ (ดู ส่วนที่ 9)
REPORT_COST_MS0ครั้งที่ 3 จำลองรายงานที่คำนวณหนัก ทดลองเสร็จแล้วตั้งกลับเป็น 0
.env ไม่ขึ้น Git

ไฟล์ .gitignore ของ repo ทีมกันไว้แล้ว เพราะในการใช้งานจริงไฟล์นี้มีรหัสผ่าน ส่วนที่ commit คือ .env.example ที่มีแต่ค่าตัวอย่าง หลักนี้ใช้ต่อในครั้งที่ 8 ตอนนำระบบขึ้น Cloud ซึ่งตั้งค่าเหล่านี้ในหน้าเว็บของผู้ให้บริการแทน

ตารางนี้ต่อยอดจากตารางแก้ปัญหาใน RUN.md ส่วนที่ 6 ถ้าเจอปัญหาที่ไม่มีในตาราง ให้คัดลอกข้อความ error บรรทัดแรกพร้อมคำสั่งที่พิมพ์ ลงในบันทึกแล็บช่องสิ่งที่ยังค้าง

ส่วนที่ 10ก่อนลุกจาก iMac ของห้องแล็บ

  1. git status ต้องไม่มีไฟล์ที่ยังไม่ได้ commit ที่ต้องการเก็บ แล้ว git pull · git push
  2. docker compose down (ไม่ต้องใส่ -v)
  3. ลบโฟลเดอร์ repo บน Desktop (ลากลงถังขยะ)
  4. Sign out GitHub ใน VS Code (ไอคอน Accounts มุมซ้ายล่าง › Sign out) และในเบราว์เซอร์ · ถ้าใช้ token ให้ลบจาก Keychain Access

ทบทวนตรวจความเข้าใจ

ตอบในใจก่อน แล้วคลิกดูแนวคำตอบ
  1. เปิด Terminal ใหม่แล้วพิมพ์ docker compose ps ได้ข้อความ no configuration file provided เกิดจากอะไรแนวคำตอบTerminal ใหม่เริ่มที่โฟลเดอร์ home ไม่ใช่โฟลเดอร์ repo คำสั่ง docker compose หาไฟล์ docker-compose.yml จากโฟลเดอร์ปัจจุบัน ต้อง cd เข้าโฟลเดอร์ repo ก่อนทุกครั้งที่เปิดหน้าต่างใหม่
  2. แก้ server.js แล้วต้อง up -d --build ใหม่ไหมแนวคำตอบไม่ต้อง โฟลเดอร์ app/ ถูก mount เข้า container และ nodemon รีสตาร์ตแอปเองเมื่อบันทึกไฟล์ ดูยืนยันใน logs -f app · ต้อง build ใหม่เมื่อแก้ package.json หรือ Dockerfile เท่านั้น
  3. แก้ REPORT_COST_MS ใน .env แล้วสั่ง restart app แต่ระบบยังเหมือนเดิม เพราะอะไรแนวคำตอบค่า environment ถูกใส่ตอนสร้าง container ส่วน restart หยุดแล้วเริ่มตัวเดิมด้วยค่าเดิม ต้องใช้ docker compose up -d ให้ Compose เห็นว่าค่าเปลี่ยนแล้วสร้าง container ใหม่ ตรวจด้วย exec app printenv REPORT_COST_MS
  4. กด Ctrl+C ในหน้าต่างที่เปิด logs -f app ระบบหยุดไหมแนวคำตอบไม่หยุด เพราะเปิดระบบด้วย up -d container ทำงานเบื้องหลัง Ctrl+C หยุดแค่การตาม log ในหน้าต่างนั้น
  5. จบแล็บบน iMac ใช้ down หรือ down -v เพราะอะไรแนวคำตอบdown พอ ปิดระบบและลบ container โดยข้อมูลยังอยู่ใน volume ส่วน -v ลบข้อมูลทิ้งทั้งหมด ใช้เมื่อตั้งใจเริ่มข้อมูลใหม่เท่านั้น ข้อมูลที่ต้องส่งอาจารย์อยู่ใน repo ไม่ได้อยู่ในฐานข้อมูลบน iMac
  6. แอปใน container ต่อฐานข้อมูลที่ db:5432 แต่โปรแกรม DBeaver บนเครื่องเราต้องต่อที่ localhost:5433 ทำไมไม่เหมือนกันแนวคำตอบแอปอยู่ในเครือข่ายของ Compose จึงเรียกฐานข้อมูลด้วยชื่อ service และพอร์ตใน container ส่วนโปรแกรมบนเครื่องเราอยู่นอกเครือข่ายนั้น ต้องเข้าทางพอร์ตของเครื่องที่จับคู่ไว้ คือ 5433 → 5432
  7. docker ps เห็น container ของทีมอื่นบน iMac เครื่องเดียวกัน แต่ docker compose ps ไม่เห็น เพราะอะไรแนวคำตอบdocker ps ดูทั้งเครื่อง ส่วน docker compose ps ดูเฉพาะโปรเจกต์ของโฟลเดอร์ปัจจุบัน ชื่อโปรเจกต์มาจากชื่อโฟลเดอร์ แต่ละทีมจึงแยกกันโดยอัตโนมัติ
  8. git push ถูกปฏิเสธเพราะเพื่อน push ไปก่อน ควรทำอย่างไรแนวคำตอบgit pull เพื่อรวมงานของเพื่อนเข้ามาก่อน ถ้าแก้คนละไฟล์จะรวมให้เอง แล้ว git push อีกครั้ง ถ้าแก้ไฟล์เดียวกันตรงเดียวกันจะเกิด conflict ให้คุยกันว่าจะเก็บส่วนไหน แก้ไฟล์ แล้ว commit
