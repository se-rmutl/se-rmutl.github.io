# ระบบ SE-WIL ส่วนที่ 1–2 (ENGSE304/ENGSE305 ภาค 2/2569) v1.5

เว็บแอปบน Google Apps Script ที่เก็บข้อมูลใน Google Sheets สำหรับหลักสูตรวิศวกรรมซอฟต์แวร์ มทร.ล้านนา

- **ส่วนที่ 1 ทะเบียนที่ฝึกและข้อตกลง SE-WIL01**
  - นักศึกษากรอกสถานประกอบการ ผู้นิเทศงาน ตำแหน่งงาน และโจทย์ แล้วส่งให้หลักสูตรตรวจ
  - อาจารย์อนุมัติหรือส่งกลับ เมื่ออนุมัติ ระบบสร้างข้อตกลงเป็น PDF จากแม่แบบ Google Docs แล้วส่งอีเมลถึงผู้นิเทศงานและนักศึกษา
  - ผู้นิเทศงานยืนยันข้อตกลงทางออนไลน์ หรืออาจารย์บันทึกว่าลงนามในเอกสารแล้วก็ได้
- **ส่วนที่ 2 Logbook และการรับรองรายสัปดาห์**
  - นักศึกษาบันทึกงานรายวันและแท็กเป็น 305 หรือ 304
  - ทุกวันศุกร์ระบบรวมรายการร่างเป็นชุดรับรอง แล้วส่งอีเมลสรุปให้ผู้นิเทศงาน ผู้นิเทศงานรับรองหรือส่งกลับรายการผ่านลิงก์เฉพาะคน
  - ชั่วโมงจะนับเมื่อรับรองแล้วเท่านั้น และแยกสะสมเป็น 305 (เป้า 300) และ 304 (เป้า 135)

## การเข้าใช้งาน

| ผู้ใช้ | วิธีเข้า |
|---|---|
| นักศึกษา อาจารย์ ผู้ดูแล | กรอกอีเมลที่ลงทะเบียนในชีต Users แล้วระบบส่งลิงก์เข้าระบบไปที่อีเมลนั้น (ใช้ได้ครั้งเดียว 30 นาที) หลังเข้าระบบ เครื่องนั้นจำการเข้าระบบไว้ 14 วัน **ไม่ต้องมีบัญชี Google** ใช้อีเมล Microsoft 365 ของมหาวิทยาลัยได้ |
| ผู้นิเทศงาน / ที่ปรึกษาร่วม | ใช้ลิงก์เฉพาะคนในอีเมลจากระบบ ไม่ต้องเข้าระบบ |

บทบาทในชีต Users:
- `student`: กรอกข้อมูลที่ฝึกและบันทึก logbook ได้
- `teacher`: เลือกนักศึกษาที่จะดูแลเองในแท็บ "จับคู่อาจารย์นิเทศ" (เห็นรายชื่อทุกคนแบบย่อ) แล้วดูรายละเอียดเฉพาะนักศึกษาที่ตนดูแล (อ่านอย่างเดียว)
- `admin`: เห็นนักศึกษาทุกคน อนุมัติ ส่งกลับ บันทึกการลงนาม และสั่งส่งสรุปรายสัปดาห์ได้
- ผู้ประสานงาน SE-WIL (อ.ธนิต เกตุแก้ว thanit@rmutl.ac.th) เป็น `admin` และเป็นผู้ติดต่อหลักของนักศึกษาและสถานประกอบการ setup() เพิ่มแถวนี้ให้เองจากค่า `COORDINATOR_EMAIL` พอร์ทัลกำหนดให้อนุมัติครบภายใน 14 พ.ย. 2569
- หัวหน้าหลักสูตรเป็นผู้ติดต่อกรณีจำเป็น ไม่ต้องมีแถวใน Users ถ้าไม่ได้เข้าระบบ

## ติดตั้ง

ขั้นตอนเต็มพร้อมกำหนดวันของภาค 2/2569 อยู่ใน `DEPLOY-2-2569.md` สรุปได้ดังนี้

1. ล็อกอินบัญชี Google ที่เป็นเจ้าของโฟลเดอร์ Drive ของรายวิชา แล้วสร้าง Google Sheet ในโฟลเดอร์นั้น
2. ใส่โค้ดจาก `src/` ด้วย clasp หรือคัดลอกเองใน Extensions > Apps Script
3. เมนู SE-WIL > **1) ตั้งค่าระบบ** แล้วอนุญาตสิทธิ์ ระบบสร้างชีต 8 แผ่น แม่แบบ SE-WIL01 และโฟลเดอร์ข้อตกลงไว้ใน**โฟลเดอร์เดียวกับชีต**
4. ตรวจชีต Config และแม่แบบ SE-WIL01
5. Deploy เป็น Web app (Execute as: Me, Who has access: Anyone) แล้วใส่ URL `/exec` ใน Config > `APP_URL`
6. เมนู SE-WIL > **2) ติดตั้งตัวจัดเวลาส่งสรุปรายสัปดาห์**
7. ทดสอบครบวงจรด้วยข้อมูลทดสอบ แล้วลบแถวทดสอบ
8. ใส่รายชื่อจริงในชีต Users

### แก้โค้ดภายหลัง
1. แก้ไฟล์ใน `src/` แล้วรัน `node test/run.js` ให้ผ่านทั้งหมด
2. ส่งโค้ดขึ้น: `clasp push -f` จากโฟลเดอร์ `deploy/` (หรือคัดลอกไฟล์ที่แก้ไปวางใน Apps Script)
3. Deploy > Manage deployments > แก้ไข (รูปดินสอ) > Version: **New version** แล้วกด Deploy

URL จะไม่เปลี่ยน ถ้ากด "New deployment" จะได้ URL ใหม่และต้องแก้ `APP_URL` กับลิงก์ในพอร์ทัลทุกที่

## ข้อควรรู้ในการใช้งาน

**โควตาอีเมล:** บัญชี Gmail ทั่วไปส่งได้ประมาณ 100 ผู้รับต่อวัน (Google Workspace ได้ประมาณ 1,500)
- อีเมลแต่ละประเภทนับดังนี้
  - ขอลิงก์เข้าระบบ 1 ฉบับ
  - อนุมัติข้อตกลง 2 ฉบับ
  - สรุปรายสัปดาห์ 1 ฉบับต่อผู้นิเทศงาน
  - ส่งรายการกลับ 1 ฉบับ
- ช่วงเปิดภาคควรทยอยให้นักศึกษาเข้าระบบ และอย่าอนุมัติข้อตกลงเกินประมาณ 30 รายต่อวัน
- ตรวจโควตาที่เหลือได้ที่เมนู SE-WIL > ตรวจโควตาอีเมลวันนี้

**อีเมลเข้ากล่องขยะ:** อีเมล Microsoft 365 ของมหาวิทยาลัยอาจคัดอีเมลจาก Gmail ไปไว้ใน Junk หรือ Quarantine
- ให้แจ้งนักศึกษาให้ตรวจ Junk
- หรือขอฝ่ายไอทีเพิ่มอีเมลของระบบในรายชื่อผู้ส่งที่อนุญาต

**แถบเตือนของ Google:** หน้าเว็บแอปจะมีแถบ "This application was created by a Google Apps Script user" อยู่ด้านบนเสมอ เป็นเรื่องปกติของบัญชีทั่วไป

**ข้อมูลส่วนบุคคล:**
- แชร์ชีตเฉพาะผู้ดูแลที่จำเป็น อาจารย์อื่นใช้ผ่านเว็บแอปแทนการเปิดชีต
- ถ้าต้องการให้อาจารย์เปิดไฟล์ PDF ข้อตกลงจากหน้าระบบได้ ให้แชร์โฟลเดอร์ข้อตกลงให้อาจารย์แบบ Viewer

**ยกเลิกลิงก์ผู้นิเทศงานที่รั่วไหล:**
1. ลบค่าในคอลัมน์ `token` ของผู้นิเทศงานคนนั้นในชีต Supervisors
2. ลิงก์เดิมจะใช้ไม่ได้ทันที
3. ระบบจะสร้างลิงก์ใหม่และส่งไปในอีเมลสรุปรอบถัดไป หรือส่งทันทีจากเมนู "ส่งสรุปรายสัปดาห์ตอนนี้"

**สำรองข้อมูล:** ใช้ File > Version history ของชีต และดาวน์โหลดเป็น .xlsx เดือนละครั้ง

**ร่องรอยการใช้งาน:** ชีต Audit บันทึกการเข้าระบบ การอนุมัติ การยืนยัน และการรับรองทุกครั้ง

## ชีตข้อมูล

| ชีต | เก็บอะไร |
|---|---|
| Config | ค่าตั้งค่า (ภาคการศึกษา ชั่วโมงเป้าหมาย วันส่งสรุป URL) |
| Users | รายชื่อผู้ใช้และบทบาท คอลัมน์ `email` `role` `student_id` `name` `phone` `section` `advisor_email` `active` ใช้หนึ่งอีเมลต่อหนึ่งคนและห้ามเปลี่ยนกลางภาค `phone` ใส่เฉพาะเบอร์อาจารย์ที่เจ้าตัวยินยอม (ควรเป็นเบอร์ที่ทำงาน) |
| Placements | ข้อมูลที่ฝึก ข้อมูลติดต่อ แผนที่ รหัสไฟล์ CV และรูป และสถานะข้อตกลงของนักศึกษาแต่ละคน |
| Supervisors | ผู้นิเทศงานและที่ปรึกษาร่วม พร้อมลิงก์เฉพาะคน |
| Logbook | บันทึกรายวัน (สถานะ `draft`, `pending`, `certified`, `returned`) |
| CertBatches | ชุดรับรองที่ส่งให้ผู้นิเทศงาน และผลการพิจารณา |
| Sessions | ลิงก์เข้าระบบและ session (เก็บเป็นค่า hash) |
| Audit | ร่องรอยการใช้งาน |

สถานะข้อมูลที่ฝึก: `draft` → `submitted` → `agreement_sent` → `signed` และส่งกลับเป็น `returned` ได้จาก `submitted` หรือ `agreement_sent`

## การทดสอบ

`test/run.js` จำลอง SpreadsheetApp, MailApp, Utilities และบริการอื่นของ Google ไว้ในหน่วยความจำ แล้วทดสอบทั้งเส้นทาง: เข้าระบบ → กรอกและส่งข้อมูลที่ฝึก → ส่งกลับและส่งใหม่ → อนุมัติ → บันทึก logbook → ส่งรับรอง → ผู้นิเทศงานยืนยันข้อตกลงและรับรองบางส่วน → แก้รายการที่ถูกส่งกลับ → สรุปรายสัปดาห์ รวมถึงการตรวจสิทธิ์ การกันสูตรในชีต และการยกเลิกลิงก์

```bash
node test/run.js      # 132 checks
```

การทดสอบนี้ไม่ได้รันบน Google จริง ส่วนที่สร้าง PDF ผ่าน DocumentApp/DriveApp จึงต้องทดสอบตามขั้นตอนที่ 6 ก่อนใช้งานจริง

- แท็บ "จับคู่อาจารย์นิเทศ" สำหรับ teacher และ admin: อาจารย์ทุกท่านเห็นรายชื่อนักศึกษาทุกคนแบบย่อ (ชื่อ รหัส sec สถานประกอบการ จังหวัด สถานะ) กด "รับดูแล" แล้วยืนยัน ยืนยันแล้วอาจารย์ท่านอื่นเลือกไม่ได้ ผู้ที่ยืนยันยกเลิกได้เอง admin กำหนดหรือเปลี่ยนให้ใครก็ได้ ทำงานภายใต้ lock กันกดพร้อมกัน
- Config ใหม่ `ADVISOR_SELF_ASSIGN` `ADVISOR_MAX` ชีต Users เพิ่มคอลัมน์ `advisor_set_by` `advisor_set_at` การจับคู่ทุกครั้งบันทึกใน Audit
- กล่อง "สิ่งที่ต้องทำ" (ต้องทำ เลยกำหนด รอ เรียบร้อย พร้อมปุ่มไปที่รายการ) "กำหนดการถัดไป" และ "คำแนะนำ" ในหน้านักศึกษา อาจารย์ ผู้ดูแล และผู้นิเทศงาน คำนวณจากสถานะจริงและกำหนดการทั้งภาค (`TERM_PLAN` ใน Config.gs ต้องตรงกับ deadlines ของพอร์ทัล ชุดทดสอบตรวจให้)
- ผู้ดูแลที่เป็นอาจารย์นิเทศด้วย (เช่น ผู้ประสานงาน) ใช้บัญชี `admin` บัญชีเดียว เลือกตัวเองในแท็บจับคู่ และกรองหน้าภาพรวมด้วย "นักศึกษาที่ฉันเป็นอาจารย์นิเทศ" ไม่ต้องมีแถว `teacher` ซ้ำ
- ไฟล์ใหม่ `Assign.gs` `Todo.gs` (รวม 17 ไฟล์) ชุดทดสอบ 302 รายการ

**v1.4.1 (8 พ.ย. 2569) ชื่อและเบอร์จากชีต Users**
- เบอร์ในคอลัมน์ `phone` ของนักศึกษาใช้เติมฟอร์มให้เท่านั้น ผู้นิเทศงาน อีเมลถึงสถานประกอบการ และข้อตกลงใช้เฉพาะเบอร์ที่นักศึกษาส่งเอง ถ้านักศึกษาลบเบอร์ เบอร์ในชีต Users จะไม่โผล่แทน (อาจารย์นิเทศและ admin ยังเห็นเบอร์ในชีต Users)
- ชื่อและรหัสนักศึกษาในข้อมูลที่ฝึกอัปเดตตามชีต Users ทุกครั้งที่นักศึกษาบันทึก และตอนอนุมัติ
- อนุมัติไม่ได้ถ้ายังไม่มีชื่อนักศึกษาในชีต Users เพื่อไม่ให้ข้อตกลงออกไปโดยไม่มีชื่อ
- ชุดทดสอบ 239 รายการ

**v1.4 (8 พ.ย. 2569) ผู้ประสานงาน SE-WIL เป็นผู้ติดต่อหลัก**
- Config ใหม่ `COORDINATOR_NAME` `COORDINATOR_EMAIL` `COORDINATOR_PHONE` (ค่าเริ่มต้น อ.ธนิต เกตุแก้ว thanit@rmutl.ac.th เบอร์ว่าง)
- หน้านักศึกษาและหน้าผู้นิเทศงานแสดงผู้ประสานงานเป็นรายชื่อแรก หัวหน้าหลักสูตรอยู่ท้ายสุดในชื่อ "กรณีจำเป็น" หน้าผู้นิเทศงานมีการ์ด "ติดต่อหลักสูตร" แยกจากข้อมูลนักศึกษา
- อีเมลถึงผู้นิเทศงานแสดงผู้ประสานงาน นักศึกษา และอาจารย์นิเทศ ไม่แสดงหัวหน้าหลักสูตร ท้ายอีเมลทุกฉบับระบุชื่อและอีเมลผู้ประสานงาน (ไม่มีเบอร์)
- ถ้าผู้ประสานงานเป็นอาจารย์นิเทศของนักศึกษาด้วย แสดงบรรทัดเดียว
- reply-to ใช้ `PROGRAM_EMAIL` ถ้าว่างใช้ `COORDINATOR_EMAIL`
- แม่แบบ SE-WIL01 เพิ่มแถว "ผู้ประสานงานหลักสูตร (ติดต่อหลัก)" แถวหัวหน้าหลักสูตรเหลือชื่อและอีเมล ต้องกดเมนู "สร้างแม่แบบ SE-WIL01 ใหม่" (แม่แบบเดิมเปลี่ยนชื่อเป็น [เลิกใช้])
- setup() เพิ่มผู้ประสานงานเป็น `admin` ใน Users ถ้ายังไม่มี และปรับคำอธิบายในชีต Config ให้เป็นฉบับล่าสุดโดยไม่แตะค่า
- ชุดทดสอบ 221 รายการ

**v1.3 (8 พ.ย. 2569) การคุ้มครองข้อมูลส่วนบุคคล**
- เบอร์โทรทุกช่องไม่บังคับ (นักศึกษา บริษัท ผู้นิเทศงาน ที่ปรึกษาร่วม) ถ้าเว้นว่าง ทุกฝ่ายติดต่อทางอีเมล ตรวจรูปแบบเฉพาะเมื่อกรอก
- นักศึกษาแก้หรือลบเบอร์ของตนเองได้ทุกสถานะ และลบ CV หรือรูปได้เอง
- เข้าถึงเท่าที่จำเป็น: บทบาท `teacher` เห็นเฉพาะนักศึกษาที่ตนเป็นอาจารย์นิเทศ บทบาท `admin` เห็นทุกคน
- ลิงก์ประกาศการคุ้มครองข้อมูลส่วนบุคคล (`help/privacy.html` ในพอร์ทัล) ในหน้าเข้าระบบ ข้อความยินยอม หน้าผู้นิเทศงาน และท้ายอีเมล อีเมลถึงผู้นิเทศงานแจ้งว่าเก็บข้อมูลใดของท่านและขอแก้หรือลบได้
- เมนู SE-WIL > "หลังส่งผลการเรียน: ลบ CV รูป และเบอร์มือถือนักศึกษา" เก็บข้อตกลงและ logbook ไว้เป็นหลักฐาน
- ชุดทดสอบ 205 รายการ

**v1.2 (8 พ.ย. 2569) ข้อมูลติดต่อ แผนที่ รูป และ CV**
- ฟอร์มข้อมูลที่ฝึก: เบอร์มือถือนักศึกษา เบอร์โทรบริษัท (บังคับ) เว็บไซต์ (ไม่บังคับ) ตำแหน่งบน Google Maps (บังคับ รับลิงก์ Google Maps หรือพิกัด) เบอร์ที่ปรึกษาร่วม (บังคับเมื่อเป็นคนละคนกับผู้นิเทศงาน)
- แนบ CV (PDF) และรูปสถานประกอบการ (JPG PNG WebP) ตรวจชนิดไฟล์จากเนื้อไฟล์ จำกัดขนาด ไฟล์เก็บในโฟลเดอร์ย่อยของโฟลเดอร์รายวิชาและไม่แชร์
- สิทธิ์เปิดไฟล์: CV เปิดได้โดยนักศึกษาเจ้าของ อาจารย์ ผู้ดูแล ผู้นิเทศงานและที่ปรึกษาร่วมของนักศึกษาคนนั้น รูปเปิดได้โดยนักศึกษาและอาจารย์ การเปิดไฟล์ทุกครั้งบันทึกใน Audit
- การ์ดผู้ติดต่อ: นักศึกษาเห็นอาจารย์นิเทศ หัวหน้าหลักสูตร ผู้นิเทศงาน ที่ปรึกษาร่วม ผู้นิเทศงานเห็นนักศึกษา อาจารย์นิเทศ หัวหน้าหลักสูตร อาจารย์เห็นทุกฝ่าย
- แม่แบบ SE-WIL01 เพิ่มเบอร์นักศึกษา เบอร์อาจารย์ หัวหน้าหลักสูตร เบอร์และเว็บไซต์บริษัท และลิงก์แผนที่ อีเมลถึงผู้นิเทศงานมีตารางผู้ติดต่อ
- ไฟล์ใหม่ `Files.gs` (รวม 15 ไฟล์) ชีต Users เพิ่มคอลัมน์ `phone` ชีต Placements เพิ่ม 8 คอลัมน์ ชุดทดสอบ 178 รายการ
