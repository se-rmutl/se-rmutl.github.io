Container คือ

  • เว็บแอปในเบราว์เซอร์
  • โปรแกรมฝั่ง server (API)
  • แอปมือถือ · แอป desktop
  • ฐานข้อมูล · งานตามเวลา
Container ไม่ใช่
  • Docker container
  • โฟลเดอร์ของโค้ด
  • หน้าจอหนึ่งหน้า
  • ตารางในฐานข้อมูล

Component คือ

  • อยู่ ข้างใน container

ความเข้าใจผิดที่พบบ่อย
  • วาด component ก่อน container
  • ตั้งชื่อตามหน้าจอ (หน้าฟอร์ม)
  • คิดว่า component = microservice

บทที่ 10 · ~15 นาที

ตรวจความเข้าใจ

ตอบในทีมก่อน แล้วค่อยเปิดเฉลย

ตอบให้ได้ภายใน 1 นาทีต่อข้อ

1. ให้หน้าเว็บเป็นที่ตรวจว่าใครอนุมัติคำขอได้ — ถูกไหม?
ไม่ถูก — เบราว์เซอร์อยู่ในเครื่องผู้ใช้ ผู้ใช้แก้หรือข้ามได้ ต้องตรวจที่ API (DEC-01, NFR-02)
2. Container ในภาพ C4 หมายถึง Docker container ใช่ไหม?
ไม่ใช่ — container คือแอปหรือที่เก็บข้อมูลที่ต้องรันเพื่อให้ระบบทำงาน
3. NFR ด้าน performance ยังไม่มีตัวเลข ควรใส่ cache ไว้ก่อนไหม?
ไม่ควร — เขียนสถานะ TBD ชี้ OI ที่รอ และบันทึกเป็น open decision
4. ระบบต้องเตือนผู้ใช้ก่อนถึงเวลานัด โดยไม่มีใครกด — ต้องเพิ่ม container อะไร?
งานตามเวลา (scheduled job) บน server ของทีม เพราะมี requirement ให้ทำงานตามเวลา
5. ลูกศรจาก Web ไป API เขียนแค่ “เชื่อมต่อ” พอไหม?
ไม่พอ — ต้องบอกว่าส่งอะไร และผ่านอะไร เช่น “เรียก API ค้นหา/ส่งคำขอ [REST/JSON · HTTPS]”

ความเข้าใจผิดที่พบบ่อย

✗ คิดว่า container = Docker
✗ วาด component ก่อน container
✗ ใส่เทคโนโลยีเกินจำเป็น (microservice, Kubernetes, message broker)
✗ ลูกศรไม่มีป้าย
✗ ตรวจสิทธิ์หรือกติกาที่หน้าเว็บ
✗ ให้หน้าเว็บต่อฐานข้อมูลตรง
✗ เลือกยี่ห้อโดยไม่มีเหตุผล
✗ ออกแบบเกิน NFR ที่ยัง TBD
